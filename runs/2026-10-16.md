**Claim and acceptance:** quoted fields must survive stream chunk boundaries.
The [claim](2026-10-16/claim.md) was saved before production edits. For example,
chunks `name,note\nAlice,"hel` and `lo"\n` should produce
`[{ name: "Alice", note: "hello" }]`, just as the unsplit CSV does.
The baseline rejected this valid input. Each scan now starts at the beginning of
the retained incomplete record with a fresh quote state. Public API signatures,
dependencies and existing assertions are unchanged.

This fix concerns CSV quote state across decoded text chunks. It does not repair

No performance improvement or universal correctness is claimed.

The criterion review reproduced a separate existing defect on both revisions:
with `indexHeader(1)`, splitting the first CRLF in
`preamble\r\n"id",note\r\n1,ok\r\n` produces no rows instead of
`[{ id: "1", note: "ok" }]`. The record separator is counted twice before the
header. The final checker retains this observation separately from the quote
regression results.
